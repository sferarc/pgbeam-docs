---
title: Agent Credentials
icon: KeyRound
description:
  Scoped, revocable Postgres credentials and MCP tokens for AI agents. The agent
  never sees your real database credentials.
---

An agent credential is a PgBeam-issued identity for one agent. It comes with a
scoped Postgres username and password and an API token for the hosted MCP
endpoint. PgBeam authenticates the credential itself and connects upstream with
your stored database credentials, so the agent never sees your real ones. Every
credential is scoped to a policy, revocable, and kill-switchable on its own.

## Create a credential

<Tabs items={["CLI", "Dashboard", "API"]}>
  <Tab value="CLI">
    ```bash
    pgbeam agents create --name analytics-bot --policy read-only
    ```
  </Tab>

<Tab value="Dashboard">
  Open your project, go to **Agents**, and select **New agent**. Pick a policy
  profile and copy the connection string and MCP URL from the result.
</Tab>

  <Tab value="API">
    ```bash
    curl -X POST https://api.pgbeam.com/v1/projects/{projectId}/agents \
      -H "X-API-Key: pbo_..." \
      -d '{"name": "analytics-bot", "policy": "read-only"}'
    ```
  </Tab>
</Tabs>

The response includes both front doors:

```bash
# Scoped Postgres connection string
postgresql://agent_4f2c:****@a1b2c3.proxy.pgbeam.app:5432/app

# Hosted MCP endpoint
https://mcp.pgbeam.app/a1b2c3   # Authorization: Bearer pba_…
```

## What a credential carries

| Field           | Description                                                             |
| --------------- | ----------------------------------------------------------------------- |
| Postgres user   | `agent_<id>`, used in the scoped connection string.                     |
| Postgres secret | Generated password. Shown once at creation.                             |
| MCP token       | `pba_…` bearer token for the hosted MCP endpoint.                       |
| Policy profile  | The rules enforced for this credential. See [Policies](/docs/policies). |
| Status          | Active, revoked, or killed.                                             |

## Revoke a credential

Revocation is immediate. The next statement on that credential is refused.

```bash title="Revoke one credential"
pgbeam agents revoke analytics-bot
```

To stop an agent without deleting it, use the [kill-switch](/docs/kill-switch).
The kill-switch pauses access with no credential rotation; revocation removes the
credential entirely.

<Callout type="warn" title="Rotate, do not share">
  Issue one credential per agent. A per-agent credential gives you a clean audit
  trail and lets you revoke or kill a single agent without affecting the others.
</Callout>

## Authentication model

PgBeam terminates agent authentication itself. The agent password is verified
against the credential, not passed through to your database. TLS is mandatory for
agent connections.
