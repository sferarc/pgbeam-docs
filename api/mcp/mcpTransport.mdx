          Model Context Protocol endpoint using the Streamable HTTP transport. Accepts JSON-RPC 2.0 requests and lets any MCP-compatible client (Claude Code, Cursor, Windsurf, custom agents) manage PgBeam resources.
          
          
          The server registers six tools, however large the API grows. Three of them wrap the public management API and are used in order: search, describe, call.
          
          - `search_endpoints({query})` finds operations by intent and returns their operation ids, methods and paths.
          
          - `describe_endpoint({operation_id})` returns one operation's path and query parameters, request body and success response.
          
          - `call_endpoint({operation_id, path_params, query_params, body})` invokes it with the caller's bearer token.
          
          The other three are read-only agent-skill tools: `list_skills()`, `get_skill({name})` and `install_skill({name})`.
          
          
          API operations are not tools themselves: pass the operation id that `search_endpoints` returns, such as `ListProjects`, to `call_endpoint`. Calling an operation id as a tool name returns an unknown-tool error.
          
          
          **Transport:** Streamable HTTP, stateless (no session id)
          
          **Protocol:** JSON-RPC 2.0; the MCP version is negotiated at `initialize`
          
          **Methods:** `initialize`, `notifications/initialized`, `tools/list`, `tools/call`, `ping`
          
          
          Prefer the CLI (`pgbeam mcp`) for local stdio transport. Use this endpoint for remote or server-to-server MCP integration.
