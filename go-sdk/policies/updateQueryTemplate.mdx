Replaces the template's name, description, SQL, parameters, include_sql
and enabled flag. The SQL is checked as on create. A statement already
admitted under the old template is not affected; the next one is
matched against the new text.

Returns 409 on a rename to a name the project already uses, and when
the update leaves the template enabled while the organization has a
live self-hosted data plane enrollment, for the same reason as create.
Setting enabled to false is still accepted.


## Usage

```go
result, err := client.Policies.UpdateQueryTemplate(ctx, "prj_xxx", "qtp_xxx", pgbeam.QueryTemplateInput{
    Name: "open_orders_for_customer",
    Sql: "SELECT id, total FROM orders WHERE customer_id = $1 AND status = 'open' ORDER BY created_at DESC",
  })
```

| body.Sql | `string` | Yes | The statement, with its parameters as $1, $2 and so on. Exactly one SELECT, INSERT, UPDATE or DELETE, at most 16384 bytes. Every placeholder must be declared in params and every declared parameter must be used. |

| body.IncludeSql | `*bool` | No | True shows the SQL text to an agent that lists the templates. Defaults to false, since a WHERE clause can itself be sensitive. |
| body.Enabled | `*bool` | No | Defaults to true, so a template is admitted as soon as it is written. False saves it withdrawn. |
