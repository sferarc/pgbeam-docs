Replaces the rule's name, statement kinds, scope, row threshold and enabled flag. An approval request already held keeps the name it was held under.

Returns 409 when the update leaves the rule enabled while the organization has a live self-hosted data plane enrollment, for the same reason as create. Setting enabled to false is still accepted.

## Usage

```typescript
const result = await api.approvals.updateApprovalRule({
  pathParams: { project_id: "prj_xxx", approval_rule_id: "apl_xxx" },
  body: {
    name: "payments deletes",
  },
});
```

## Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| pathParams.project_id | `string` | Yes | Unique project identifier (prefixed, e.g. prj_xxx). |
| pathParams.approval_rule_id | `string` | Yes | Unique approval rule identifier (prefixed, e.g. apl_xxx). |
| body.name | `string` | Yes | Label shown to the reviewer on every approval request this rule holds. Must be unique within the project and not blank. |
| body.statement_kinds | `ApprovalRuleStatementKind[]` | No | Statement kinds the rule holds. Empty or omitted holds every kind. |
| body.schema_name | `string` | No | Schema to scope the rule to. Null, empty or omitted matches every schema. |
| body.relation_name | `string` | No | Relation to scope the rule to. Null, empty or omitted matches every relation. Without a schema it matches that name in every schema. |
| body.min_affected_rows | `number` | No | Hold only statements affecting at least this many rows. Must be at least 1. Null or omitted holds every matching statement. The count is taken in a rolled-back trial run; a statement that reports no count (DDL, a batch, a data-modifying CTE) is held regardless. |
| body.enabled | `boolean` | No | False switches the rule off, so it holds nothing. |

## Response

`Promise<ApprovalRule>`: updated approval rule.
